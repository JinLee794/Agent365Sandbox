## Quick Start

```bash
# 1. Clone and navigate
git clone <repo>
cd Agent365Sandbox/notebooks

# 2. Run Blueprint setup (PowerShell)
pwsh a365.ps1 -Step all

# 3. Create Python environment
python -m venv venv
source venv/bin/activate           # macOS/Linux
# OR .venv\Scripts\activate         # Windows

# 4. Install dependencies
pip install -r requirements.txt

# 5. Launch Jupyter
jupyter lab

# 6. Open notebooks in this order:
# - 01-validate-configuration.ipynb (verify setup)
# - 05-azure-infra-setup.ipynb (deploy Azure AI Search)
# - 06-search-rbac-demo.ipynb (configure RBAC)
# - 07-agentic-retrieval-knowledge-base.ipynb (KB + agents)
# - 08a-foundry-setup.ipynb → 08b-foundry-agents.ipynb (Agent Framework)
```

## Configuration

### Step 1: Create Blueprint (One-Time Setup)

The `a365.ps1` script creates your Agent Identity Blueprint in Entra ID.

```powershell
cd notebooks
pwsh a365.ps1 -Step all
```

**What it creates:**
- ✅ App registration in Entra ID
- ✅ Service Principal with credentials
- ✅ OAuth scope & identifier URI
- ✅ `.env` file with configuration

**Prerequisites:**
- Microsoft Graph PowerShell SDK
- Owner/Application Developer role in Entra ID

**Output:** `.env` file in `notebooks/` directory

### Step 2: Configure Environment

The `.env` file contains all configuration. **Do not commit this file.**

```env
# Entra ID (from a365.ps1)
AZURE_TENANT_ID=xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
AZURE_CLIENT_ID=xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
AZURE_CLIENT_SECRET=xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
AGENT_BLUEPRINT_PRINCIPAL_ID=xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx

# Azure (created by Notebook 05)
AZURE_SUBSCRIPTION_ID=xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
AZURE_RESOURCE_GROUP=rg-agent-blueprint-demo
AZURE_SEARCH_SERVICE_NAME=<auto-generated>

# Azure OpenAI (for Notebook 08, optional)
AZURE_OPENAI_API_KEY=sk-...
AZURE_OPENAI_ENDPOINT=https://<account>.openai.azure.com/
AZURE_OPENAI_CHAT_DEPLOYMENT_NAME=gpt-4o

# Alternative: Use OpenAI instead of Azure OpenAI
```

## Azure Search RBAC Setup

### Issue: Service Principal Lacks Search Permissions

If you see this error in Notebook 08:

```
AADSTS82001: Agentic application 'xxx' is not permitted to request app-only tokens for resource '880da380-985e-4198-81b9-e05b1cc53158'
```

Your service principal needs explicit Search permissions. Choose one solution below.

### Solution 1: Grant Search Index Data Reader Role (Recommended)

Assign the service principal the Search Index Data Reader role on your Search service.

```bash
# Get service principal object ID
SP_OBJECT_ID=$(az ad sp show --id $AZURE_CLIENT_ID --query id -o tsv)

# Get Search service resource ID
SEARCH_ID=$(az search service show \
  --resource-group $AZURE_RESOURCE_GROUP \
  --name $AZURE_SEARCH_SERVICE_NAME \
  --query id \
  -o tsv)

# Grant Search Index Data Reader role
az role assignment create \
  --assignee $SP_OBJECT_ID \
  --role "Search Index Data Reader" \
  --scope $SEARCH_ID

# Verify assignment
az role assignment list \
  --assignee $SP_OBJECT_ID \
  --scope $SEARCH_ID \
  --output table
```

**After assignment:**
1. Restart Python kernel
2. Re-run Notebook 08 Step 3
3. Should see "Using RBAC (AAD) authentication" instead of "Using Admin Key"

### Solution 2: Use User-Assigned Managed Identity

Instead of a service principal, use a managed identity for better security.

```bash
# Create user-assigned managed identity
az identity create \
  --resource-group $AZURE_RESOURCE_GROUP \
  --name agent-blueprint-identity

# Get identity's principal ID
IDENTITY_PRINCIPAL_ID=$(az identity show \
  --resource-group $AZURE_RESOURCE_GROUP \
  --name agent-blueprint-identity \
  --query principalId \
  -o tsv)

# Grant Search permissions
az role assignment create \
  --assignee $IDENTITY_PRINCIPAL_ID \
  --role "Search Index Data Reader" \
  --scope $SEARCH_ID

# Update .env
echo "AGENT_BLUEPRINT_PRINCIPAL_ID=$IDENTITY_PRINCIPAL_ID" >> .env

# Remove client secret-related vars (if using managed identity)
# Managed identities don't need AZURE_CLIENT_SECRET
```

### Solution 3: Interactive Azure CLI Login (Development Only)

For local development, authenticate with your user account instead.

```bash
# Login interactively
az login

# Get your user's object ID
USER_OBJECT_ID=$(az ad signed-in-user show --query id -o tsv)

# Grant yourself Search permissions
az role assignment create \
  --assignee $USER_OBJECT_ID \
  --role "Search Index Data Reader" \
  --scope $SEARCH_ID

# Update .env (comment out service principal vars)
# AZURE_CLIENT_ID=...       # Comment out
# AZURE_CLIENT_SECRET=...   # Comment out
# AGENT_BLUEPRINT_PRINCIPAL_ID=<your-user-id>

# DefaultAzureCredential will use Azure CLI credentials
```

### Verifying RBAC Setup

```bash
# Check role assignments
az role assignment list \
  --scope $SEARCH_ID \
  --output table

# Expected output:
# RoleDefinitionName              Scope
# ────────────────────────────────────────────────
# Search Index Data Reader        /subscriptions/...
```

### RBAC Fallback in Notebooks

If RBAC fails, notebooks automatically fall back to **admin key authentication**:
- ✅ Works immediately (no permission changes needed)
- ⚠️ Not recommended for production (less secure)
- 📌 Prints clear instructions for RBAC setup

## Troubleshooting

### "AADSTS65001: User or admin has not consented"

**Cause:** App permissions not granted in Entra ID

**Solution:**
```powershell
# Re-run blueprint setup
pwsh a365.ps1 -Step all

# Or manually grant admin consent in Azure Portal:
# Entra ID > App registrations > <your-app> > API permissions > Grant admin consent
```

### "Module not found" errors

**Cause:** Missing Python packages

**Solution:**
```bash
# Reinstall dependencies
pip install --upgrade -r requirements.txt

# Or manually install specific packages
pip install azure-search-documents azure-identity azure-cognitiveservices-search agent-framework --pre
```

### "az: command not found"

**Cause:** Azure CLI not in PATH

**Solution:**
```bash
# Check if installed
which az          # macOS/Linux
where az          # Windows

# If missing, install:
# macOS: brew install azure-cli
# Linux: curl -sL https://aka.ms/InstallAzureCLIDeb | bash
# Windows: winget install Microsoft.AzureCLI
```

### "403 Forbidden" on Search queries

**Cause:** RBAC role assignment not propagated

**Solution:**
1. Verify role assignment exists: `az role assignment list --assignee <ID>`
2. Wait 1-2 minutes for propagation
3. Restart Python kernel
4. Retry query

### "Bicep deployment failed"

**Cause:** Missing or invalid parameters

**Solution:**
```bash
# Check Bicep syntax
bicep build foundry-resources.bicep

# Check parameter file
cat foundry-deployment-params.json

# Run deployment with diagnostics
az deployment group create \
  --name foundry-setup \
  --resource-group $AZURE_RESOURCE_GROUP \
  --template-file foundry-resources.bicep \
  --parameters foundry-deployment-params.json \
  --debug
```

### "LLM not configured" warning in Notebook 08

**Cause:** Missing AZURE_OPENAI_* or OPENAI_API_KEY

**Solution:** Add one to `.env`:

```bash
# Option 1: Azure OpenAI
echo "AZURE_OPENAI_API_KEY=sk-..." >> .env
echo "AZURE_OPENAI_ENDPOINT=https://<account>.openai.azure.com/" >> .env

# Option 2: OpenAI
echo "OPENAI_API_KEY=sk-..." >> .env
```
